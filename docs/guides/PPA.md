# PPA 支持核对

2026-11-10 核对官方 esp-hal main，提交 `e045405e6f036a7d8b2ef22bc877457dc3e6eba2`。

官方 [PR #6476](https://github.com/esp-rs/esp-hal/pull/6476) 于 2026-11-05 合并，新增的是 ESP32-S31 的阻塞式 SRM（缩放、旋转、镜像及颜色转换），不是 ESP32-P4 驱动。

该提交的 [P4 芯片配置](https://github.com/esp-rs/esp-hal/blob/e045405e6f036a7d8b2ef22bc877457dc3e6eba2/esp-metadata/devices/esp32p4/soc.toml) 中，`device.pixel_accelerator.support_status` 仍为 `not_supported`；S31 为 `partial`。`ppa` 模块受 `pixel_accelerator_driver_supported` 条件控制。

工程目前采用本地修补的 esp-hal 1.2.2。直接升级 main 不会为 P4 提供可用 PPA API。此次仅核对兼容性，没有更改 HAL、烧录 PPA 固件或宣称获得性能收益。

P4 硬件有 PPA，参考 [官方 P4 PPA 文档](https://docs.espressif.com/projects/esp-idf/en/latest/esp32p4/api-reference/peripherals/ppa.html)。若继续实验，需要先做纯 Rust 的 P4 寄存器、时钟及 DMA2D 适配，再用独立例程验证 RGB565 拷贝、2 倍缩放、PSRAM 缓存一致性和 DSI 并发；不能直接移用 S31 的 HP_SYS 寄存器路径。

PPA 可以减少 CPU 像素处理工作，但仍读写内存，不能据此保证减少 PSRAM 总线争用。现有双缓冲及缓存互斥修复需要保留。按当前内存约束，不恢复整幅逻辑画面缓存，也不分配大型内部 SRAM 中间缓冲。

## 本地 P4 实现与 UI 接入（2026-11-10）

在本地 esp-hal 增加 `src/ppa.rs`，参考上述 PR 的 SRM API、描述符及缩放/旋转规则；
P4 时钟使用 HP_SYS_CLKRST，DMA2D 使用官方 P4 hw_ver3 寄存器偏移（PAC 0.3 未包含该模块）。
未引入 C 源码或 C 构建。`Srm::take()` 通过跨核原子标志独占 PPA 和整个 DMA2D，避免重复实例。
现阶段支持 RGB565/RGB888/ARGB8888；YUV、GRAY 显式拒绝，尚未实现 BLEND/FILL 引擎或异步 API。

采用 16×16 宏块和 18×18 DMA 输入边界；P4 的选择位必须为 1。
实现 ESP-IDF DIG-734 小尾块 FIFO 绕过处理，并先连接 SRM 再等待 DMA RESET_AVAIL。
调用阻塞，完成超时为 1 秒，返回错误前必须停止并排空 DMA；若排空失败则 panic，不能释放仍由硬件使用的缓冲。

源/目标支持内部 SRAM 和 PSRAM，目标地址与长度要求 128 字节对齐。
复用现有跨核缓存互斥，目标仅维护覆盖写入矩形的行范围及边界缓存行；保持外围像素。
两个描述符各占 128 字节栈空间，不分配静态图像缓存或堆空间。

### 独立演示

`cargo build --release --bin ppa_demo`，源码 `src/bin/demos/ppa_demo.rs`。
左侧 PPA 2 倍双线性缩放、右侧 CPU 整数复制，每 2 秒旋转一次。
使用 `--features verify-static` 时，在显示启动前关闭 PPA，左右都由 CPU 绘制，以隔离显示问题。
演示使用现有双帧缓冲和额外 32 KiB PSRAM 源图，内部 SRAM 验证图合计 1 KiB。

P4 v3.1 实机已通过：128×128 RGB565 拷贝逐字节比较；16 种旋转/镜像组合；
RGB565 转 RGB888/ARGB8888；内部 SRAM 拷贝；连续 8 次 2 倍均匀图缩放；
17×19 非整宏块输入的四个旋转方向。正常演示在 DSI 扫描同时运行超过 100 次传输未报错。
初版 128×128 拷贝约 0.8 ms，DSI 同时运行的 2 倍缩放/旋转约 2.1–2.2 ms，
这是包含缓存维护的整次调用耗时，不是 UI FPS 或与 CPU 同条件比较的提速倍数。

用户发现红色边缘偏高/黑线：左右 PPA/CPU 对照均存在，关闭 PPA 后纯 CPU 显示仍复现；
DMA 输出区域读回黑色像素数为零。该现象尚未修复，不能归结为 PPA 缩放像素错误，需另查显示路径。

### Tiny/Pocket UI

共享 `src/desktop/display.rs` 的 DrawTarget 对面积至少 4096 逻辑像素、高度至少 8 的纯色矩形启用 PPA。
将 16×16 同色小图缩放到物理矩形大小，直接写现有后台显存；整数尺寸可由 1/16 缩放步进精确表达。
小图为 512 字节内部 SRAM，驱动描述符另约 256 字节临时栈；无额外整屏/逻辑画面缓存。
文字、抗锯齿轮廓、小图元继续由 CPU 绘制，Slint 渲染路径未修改。
传输错误安全排空后关闭本次运行的硬件加速，并由 CPU 完整补画该矩形。
主核每 5 秒记录 PPA 填充次数和失败次数；显示核不输出日志。

## 30 Hz 扫描配置

按用户要求，将 Tiny/Pocket 共用显示后端的扫描时序改为 VBP=156、VFP=1023，
保留实际 60 MHz 像素时钟、HFP=52、HSW=20、HBP=20、VSW=4、720×1280。
总行长 812、总行数 2463，计算扫描频率 `60000000/(812*2463)=30.00018 Hz`。
DSI host 的 VFP 字段只有 10 位，不能直接写 1169；用后肩分担额外空白行。
RGB565 读取有效像素的平均数据量从约 103.3 MB/s 降到 55.3 MB/s（仅理论有效像素，非总线实测）。
双缓冲仍等待两个新 VSYNC 后复用，不能保证业务 FPS 随扫描降频提高；需实机确认画面和拖动。

30 Hz 配置已编译、烧录并启动。连续列表滚动统计：9.2、9.6、9.8、9.4、9.8 FPS，
平均绘制加提交耗时约 64.2–64.9 ms，PPA 失败均为 0；之前约 74–75 ms。
这是串口实测的业务更新速率；扫描 30.00018 Hz 为时序计算值。画面是否闪烁/错位仍待用户确认。
