# ESP32-P4 双核 CPU 使用率统计方案

2026-10-31。当前固件仅记录 UI 绘制耗时、音频任务耗时等局部指标，尚未实现 CPU 使用率计数。

## 统计口径

分别对每个核心在固定一秒窗口累积真正的空闲等待时间：

`CPU 使用率 = 100 × (窗口时间 − 空闲时间) / 窗口时间`

例如核心 0 一秒内空闲 700 ms，使用率约 30%。双核应分别报告；两个同频核心的平均利用率
可以取两者平均，不能把相加后的 200% 当成单核百分比。

空闲等待应在调度器无就绪任务、进入 WFI 的路径测量，不能通过 UI 帧率、循环次数或
单个任务的绘制耗时反推。必须明确中断时间的归属；若在开中断的等待外计时，需要扣除
落入该区间的 ISR 执行时间，避免把中断工作误算为空闲。

## 当前工程的限制

- 核心 0 使用 Embassy 0.9.1。已检查本机该版本 `src/arch/riscv32.rs`：executor poll 后，
  在临界区检查工作标记，确实没有任务才执行 WFI，离开临界区后处理中断。
- `diagnostics::run` 使用持续 `yield_now()`，这会让任务再次就绪，不代表核心休眠。
  时间轮询和其他循环也要逐个审查。现状可能测到很高的忙碌率，但不等于有效业务计算很多。
- 核心 1 当前 Slint 循环中有 `Delay::delay_millis`、同步 VSYNC 等待，忙等仍消耗 CPU。
  真正要降低利用率，需要把这些等待改为有唤醒保证的定时器/中断等待，不能仅改计数口径。
- CPU 等待 PSRAM/Flash/总线时，也不能简单归到空闲；带宽瓶颈需要独立测量。

## 建议实施顺序

1. 先按核心统计业务阶段时间：触摸、Slint 状态更新、绘制、缓存写回、换帧等待，
   主核保留音频处理耗时、USB 收包和 DMA 重启指标。阶段墙钟耗时不是完整 CPU 使用率。
2. 审查持续自唤醒任务；仅在没有日志等工作时等待事件，保留音频的低延迟要求。
3. 在 executor 的安全空闲路径记录空闲累计时间；第二核同样建立定时器与中断唤醒机制。
   不直接在主循环任意位置插入 WFI，否则可能丢失唤醒或错过 UI/音频截止时间。
4. 每核使用低开销累计计数，主核每秒汇总输出；不在高频中断或每个像素写入时打印。

这次只记录方案，不在 Slint 迁移期间同时改变调度器，避免把 UI 和音频异常混到一起。

参考：[Embassy 0.9.1 RISC-V executor](https://docs.embassy.dev/embassy-executor/0.9.1/riscv32/struct.Executor.html)。
