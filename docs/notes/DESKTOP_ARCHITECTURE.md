# 复合固件职责与资源归属

本页保留设计约束，不作为当前全部功能已完成验证的声明。

## 建议的职责与资源归属

| 资源/功能 | 所有者 | 其他核心如何使用 |
| --- | --- | --- |
| PSRAM 配置 | 主核启动阶段，一次性完成 | 初始化完成后再启动副核 |
| 双缓冲显存、MIPI、VDMA、显示中断 | 副核 | 主核只发布视图数据，不写显存 |
| GT911、运行期 I2C1 | 副核 | 音频若需运行期 codec 配置，发送请求给所有者 |
| USB 控制器、HID/VIA、UAC2（HS 复合桌面） | 主核 | 副核发送按键事件，读取 USB 状态 |
| I2S/DMA 与音频缓冲 | 主核 | UI 只发送控制命令，不接触样本缓冲 |
| C5 SDIO、Wi-Fi、BLE、网络栈、校时 | 主核 | 副核发扫描/连接请求，接收结果 |
| 键位配置与持久化 | 主核 | 副核使用带版本的配置快照 |

不把所有数据都塞入一个全局锁。最新状态（时间/IP/连接状态）允许覆盖；
扫描/连接请求使用有界命令队列并明确忙状态；按键释放不可静默丢弃，需要
溢出后的全释放/状态重同步策略。ISR 只确认中断、更新计数或唤醒任务。

## 启动与验证边界

主核初始化 PSRAM、静态缓冲及持久配置，配置 ES8311 后移交 I2C1 给副核。
显示副核持有帧缓冲及显示外设；跨核只交换状态快照与有界命令。
Flash 写入须先完成双核停驻与恢复协议，避免另一核心同时从 Flash 取指。

显示与无线共存已完成独立验证，见 [共存验证](COEXIST_VERIFY.md)。
独立路径通过不能代替 USB、音频、无线、触摸同时工作的完整回归；
缓存持锁时间对实时性及长期音频稳定性的影响仍需验证。

## UI 核可承载的业务（2026-11-07）

当前 Tiny/Pocket 副核已负责 GT911、触控板手势、页面事件、主页动画和绘制。
适合进一步集中到副核的是页面状态机、输入校验、列表整理、键位到 HID report 的转换、
宏执行时序以及时间/天气的展示格式化。实际 USB report 发送仍归主核，跨核使用有界队列；
按键释放与拥塞恢复必须保留。图像解码或像素转换应分片，不能一次长时间阻塞触摸。
网络服务、校时、天气请求不等于这些功能的展示逻辑，网络 I/O 可继续留在主核。

若为了读卡器吞吐，可以研究将 SD 块 I/O 工作任务放在副核，MSC BOT 和 USB 端点仍留主核，
通过两块内部 SRAM 缓冲及明确所有权交接重叠执行。但这不是直接移动函数：当前
`src/desktop/display.rs` 在绘制后同步等待 3 次 VSYNC，并在循环尾忙等 5 ms，
直接挂入同一串行循环会增加 I/O 延迟。需要先改为可让出执行权的显示调度，核对共享
SDMMC 的中断绑定、唤醒、缓存锁、取消和 Flash 停驻协议。两个核不会增加 SDMMC 引擎数，
因此此方案收益尚未测量，不优先于同核异步双缓冲流水线。

USB/UAC2、I2S DMA 补给、音频反馈先保留主核，避免和不可抢占的渲染混用同一执行循环。
Flash 写入也不应仅因迁核就视为不影响音频：现有停驻与取指/缓存限制仍存在。
